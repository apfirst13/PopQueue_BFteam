=== HOW GIT_SHA IS PASSED TO CLOUD RUN ===
1. ใน GitHub Actions Workflow (`.github/workflows/deploy.yml` บรรทัด 75):
   ค่า `IMAGE_TAG` ถูกกำหนดจาก `${{ inputs.image_tag || github.sha }}` ซึ่งเป็น 40-character Git Commit SHA
2. ในขั้นตอน Docker Build (`deploy.yml` บรรทัด 115):
   สั่ง `docker build --build-arg GIT_SHA="$IMAGE_TAG" --tag "$IMAGE" .` ส่งต่อตัวแปร commit เข้าสู่ build argument
3. ใน `Dockerfile` (บรรทัด 59-60):
   ประกาศ `ARG GIT_SHA="development"` และแปลงเป็น Environment Variable ถาวรใน Runtime Container ด้วย `ENV GIT_SHA=$GIT_SHA`
4. เมื่ออิมเมจนี้ถูกนำไป Deploy บน Cloud Run (`deploy/release.sh` สั่ง `gcloud run services update popqueue --image $DEPLOYED_IMAGE`):
   คอนเทนเนอร์บน Cloud Run จะมี Environment Variable `GIT_SHA` บรรจุค่า Commit SHA นั้นอยู่โดยอัตโนมัติ
5. ในโค้ด Node.js (`server/src/app.ts` บรรทัด 31):
   `commit: process.env.GIT_SHA || 'dev'` จะอ่านค่าจาก `process.env.GIT_SHA` และคืนค่า SHA เต็มของ commit ที่ deploy
6. หากไม่ได้ตั้งค่า (Local execution หรือสภาพแวดล้อมที่ไม่มีตัวแปร ENV `GIT_SHA`):
   Endpoint `/api/health` จะคืนค่า fallback เป็น `"dev"` (`{"status":"ok","commit":"dev"}`)

=== CONCLUSION ===
- GitHub Actions ส่ง commit SHA ผ่าน `docker build --build-arg GIT_SHA="$IMAGE_TAG"`
- `Dockerfile` แปลง ARG เป็น `ENV GIT_SHA=$GIT_SHA` ฝังลงใน production image
- หาก environment variable `GIT_SHA` ไม่ถูกตั้งค่า `/api/health` จะคืน `"dev"` เสมอ
